Any AI tool that speaks MCP over HTTP can use reBrowser. Adding the MCP server connects the two, and installing the reBrowser skill on top improves the experience.

The MCP syntax varies by tool, and so does the way skills are loaded. Here are the tools we have documented so far.

First, grab the endpoint URL from reBrowser. Open a new tab, click **MCP** in the sidebar, and click **Copy** at the top of the page. It looks like this:

```text
http://127.0.0.1:9200/mcp
```

Now pick your AI tool below.

<Note>
The examples name the server `reBrowser`, matching the one-click setup. The name is yours to choose, but whatever you pick is the name your AI tool will know the browser by.
</Note>

## Install the skill

The skill is one `SKILL.md` file, published from [the BrowserOS repository](https://github.com/BlueOriginAI/reBrowser/tree/main/skills/rebrowser). Most agents read skills from a shared `.agents/skills` directory, and the quickest way to put it there is the [skills.sh](https://skills.sh) CLI:

```bash
npx skills add BlueOriginAI/reBrowser --skill rebrowser
```

<Warning>
Keep the `--skill rebrowser` flag. Without it the command installs every skill published from that repository, including several we use to work on BrowserOS itself, which have no business in your agent.
</Warning>

That writes `./.agents/skills/rebrowser/SKILL.md` in the current project and symlinks it for agents that use their own directory. Add `-g` instead to install it once for every project.

Not every agent reads `.agents/skills`, so check your tool below.

## Hermes Agent

[Hermes Agent](https://hermes-agent.nousresearch.com) from Nous Research supports connecting to external HTTP MCP servers via its YAML config. Full details in [Hermes' MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp).

Open `~/.hermes/config.yaml` and add a `mcp_servers` entry:

```yaml
mcp_servers:
  reBrowser:
    url: "http://127.0.0.1:9200/mcp"
```

Then reload Hermes:

- Inside an existing `hermes chat` session, run `/reload-mcp`.
- Or restart Hermes.

Hermes also has a CLI command that adds a server interactively: `hermes mcp add reBrowser`. Either path works.

**Adding the skill.** Hermes does not read `.agents/skills`. It keeps skills in `~/.hermes/skills/`, so install it from the file directly:

```bash
hermes skills install https://raw.githubusercontent.com/BlueOriginAI/reBrowser/main/skills/rebrowser/SKILL.md
```

Check it landed with `hermes skills list`, or `/skills` inside a chat session. Hermes loads the name and description up front and pulls the full text only when it needs it, so the skill costs almost nothing until it is used. Full details in [Hermes' skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills).

## Vercel AI SDK

The [Vercel AI SDK](https://ai-sdk.dev/) supports MCP tools via the `@ai-sdk/mcp` package. Full details in [the AI SDK MCP docs](https://ai-sdk.dev/docs/ai-sdk-core/mcp-tools). Point the client at reBrowser's endpoint URL, pull the tools, and pass them into `streamText` or `generateText`.

```javascript
import { createMCPClient } from '@ai-sdk/mcp';
import { streamText } from 'ai';

const mcpClient = await createMCPClient({
  transport: {
    type: 'http',
    url: 'http://127.0.0.1:9200/mcp',
  },
});

const tools = await mcpClient.tools();

const result = await streamText({
  model: 'xai/grok-4.5',
  tools,
  prompt: 'Open the running reBrowser tab and summarise what my agent just did.',
  onFinish: async () => {
    await mcpClient.close();
  },
});
```

The AI SDK docs recommend closing the client once you're done. In streaming code that means `mcpClient.close()` inside `onFinish`. In non-streaming code, use a `try` / `finally` block.

**Adding the skill.** The AI SDK is a library rather than an agent, so nothing discovers skills for you. Run the `npx skills add` command above, then read the file into your system prompt:

```javascript
import { readFile } from 'node:fs/promises';

const skill = await readFile('.agents/skills/rebrowser/SKILL.md', 'utf8');

const result = await streamText({
  model: 'xai/grok-4.5',
  tools,
  system: skill,
  prompt: 'Book me a table for four on Friday.',
});
```

For more than one skill, the AI SDK's [agent skills guide](https://ai-sdk.dev/cookbook/guides/agent-skills) covers loading names and descriptions up front and fetching the full text on demand with a `loadSkill` tool.

## OpenClaw

[OpenClaw](https://openclaw.ai) is an open-source personal AI assistant that can act as an MCP client. Full details in [OpenClaw's MCP docs](https://docs.openclaw.ai/cli/mcp).

The fastest path is the CLI:

```bash
openclaw mcp add reBrowser --url http://127.0.0.1:9200/mcp --transport streamable-http
```

Or edit `~/.openclaw/openclaw.json` directly:

```json
{
  "mcp": {
    "servers": {
      "reBrowser": {
        "url": "http://127.0.0.1:9200/mcp",
        "transport": "streamable-http"
      }
    }
  }
}
```

Verify the connection with the built-in doctor:

```bash
openclaw mcp doctor reBrowser --probe
```

**Adding the skill.** OpenClaw already reads `.agents/skills`, both in the workspace and at `~/.agents/skills`, so the `npx skills add` command above is enough and there is nothing else to wire up. If you would rather use OpenClaw's own installer, it takes a skills.sh reference:

```bash
openclaw skills install skills-sh:BlueOriginAI/reBrowser/rebrowser
```

Add `--global` to install it for every workspace. Confirm with `openclaw skills list`. Full details in [OpenClaw's skills docs](https://docs.openclaw.ai/tools/skills).

## Any other MCP-compatible AI tool

The pattern is the same: paste `http://127.0.0.1:9200/mcp` into the AI tool's own MCP server config, using whatever syntax that tool expects. reBrowser's endpoint uses **Streamable HTTP** transport (per the current MCP spec), so any client that supports Streamable HTTP works.

For the skill, run `npx skills add BlueOriginAI/reBrowser --skill rebrowser` and then check where your agent looks for skills. Most read `.agents/skills` and will find it with no further work. If yours keeps them somewhere of its own, copy `.agents/skills/rebrowser/SKILL.md` into that directory, or point its own installer at the file:

```text
https://raw.githubusercontent.com/BlueOriginAI/reBrowser/main/skills/rebrowser/SKILL.md
```

If you get your AI tool talking to reBrowser and want to help others do the same, please [open a discussion](https://github.com/orgs/browseros-ai/discussions) with the setup steps.

## Session lifetime and reconnecting

For clients using a stateful MCP connection, the server-issued `Mcp-Session-Id` HTTP header identifies the **transport session**. Its inactivity timeout is finite: **24 hours**. MCP requests refresh that timeout; SSE heartbeats alone do not. Closing an SSE stream does not delete the transport session, so a client can reopen it with the same still-valid ID.

The browser's **work session** is separate: it normally closes after 30 minutes of inactivity. When that natural close is known, the next request on a valid legacy transport starts a fresh work session without reporting a user Stop. It does not restart old tasks or automatically reclaim old tabs. An explicit Stop is still reported before a subsequent legacy request can start new work.

A deleted, expired, unknown, or pre-restart transport ID still returns HTTP 404 (`Session not found`). The MCP client must discard that ID and **initialize a new connection**; reload or reconnect the MCP server in your AI tool if its client does not do this automatically. Transport sessions are in memory and do not survive a backend restart. Changing the tool argument `session` cannot fix this HTTP 404: that argument is a work-session handle for clients without a transport ID, not the HTTP header.

Do not blindly replay a tool call after a timeout or lost response: the operation may already have run. Reconnect first, inspect the current state, and only then decide whether another operation is needed.
