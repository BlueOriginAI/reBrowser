# Account and sync security maintenance

This source tree versions the native account/sync overlay from the installed 0.1.2 runtime, its WebUI/profile integration and its security tests. The old external source repository was removed during maintenance; the 0.1.2 bundled source archive was recovered into an independent Git repository before applying the fixes. The recovery commit records the original snapshot identity.

Backend 0.0.63 applies a single loopback Host/Origin/Fetch-Metadata boundary to REST and MCP. Unknown browser sources, forged authorities and untrusted preflights are rejected before handlers; browser CORS is limited to the signed cockpit extension. The opaque native recorder exception is restricted to its ingestion endpoint. Native MCP clients keep their originless JSON transport contract. Build and packaging gates require both instance ownership and HTTP-origin policy capability markers.

Sync path policy v2 rejects encoded authentication routes, nested escapes, encoded separators and invalid UTF-8 while preserving ordinary international and escaped-space paths. Native C++ and SaaS Worker use the same 27-case fixture. The production C++ helper can be tested independently of Chromium with `python3 packages/reBrowser/security/check_sync_url_policy.py`; the full native protocol/auth tests still require the Chromium build tree.

Formal macOS packaging also requires `rebrowser-sync-url-policy=2;` in the actual Chromium framework. Clearing the pending-build plist flag cannot make an old framework pass. The marker is retained by the production protocol translation unit; packaging regressions cover old-framework rejection and bounded-memory scanning.

The initial local 0.1.3 maintenance installation replaced only the Rust backend. The resumed full Chromium build completed on 2026-10-26 from commit `167c3a1271405c77e8edd92394819d1e7328b991`: nine native URL/protocol tests and seven OAuth tests passed. The rebuilt framework and backend 0.0.63 were packaged and installed, with the native URL marker and package/framework hashes verified. Installed acceptance confirmed Claude Code on port 9010, blocked cross-origin management access, trusted extension access and unchanged global configuration across temporary-instance startup and exit. Native, Worker and installed-backend validation remain separate. A local app with `RemocodeNativeSecurityBuildPending=true` is rejected by ordinary formal package gates; only an explicit local-maintenance packaging option may produce its installer.

The Worker security module was first deployed as version `e38afcf4-608e-4702-98da-8d3f85635217`. A later business deployment retained the module but switched its entrypoint to `site.js`. Version `dc7bba99-7bca-4c44-bb7f-b04850293d1c` restores the `sync-security.js` entrypoint while preserving both current module bodies, settings and bindings. SaaS source commit `ed4f124ab89a3754b9525910c736691cd36088b5` also fixes the business deployment helper to preserve protected entrypoints and auxiliary modules, reject stale snapshots and detect concurrent production changes; five focused deployment regressions passed. Final production readback and anonymous HTTP checks passed. Sync remains disabled because production has neither `SYNC_API_ENABLED` nor `SYNC_OBJECTS`; no authenticated production sync-data acceptance is claimed. The source-controlled scoped wrapper and deployment recipe live in the SaaS control-plane `SCOPED-SYNC-SECURITY.md`.
